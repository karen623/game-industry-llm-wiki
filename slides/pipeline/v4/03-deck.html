這是我第一個主題做簡報時的紀錄。每一道關卡都有抓到問題、也都修好了，但發佈後我發現簡報在介紹自己怎麼做，而不是在交作業。所有檢查都在問「做得對不對」，沒有一關在問「做的是不是對的東西」。
反思

哪個節點最常出錯？

最常錯：製作 HTML；代價最大：需求／大綱

最常錯＝製作 HTML（12 次）
C3 自動抓到，幾分鐘修好，代價低

代價最大＝需求／大綱（2 次）
沒有檢查抓到：簡報重做、主題重做

來源：reports/reflection.md

最常出錯的是製作 HTML，12 次，但都是排版問題，自動檢查幾分鐘就修好。代價最大的是最上游的需求和大綱，只錯兩次：一次是簡報定位錯，整份重做；一次是我把 LLM Wiki 的方法和主題搞混，整個主題重做。這兩次都沒有任何檢查抓到。
反思

檢查往前移到了哪裡？

R0 需求關卡＋檢查跟著主題調整

定位錯發佈後→R0 需求確認
方法和主題搞混換主題→R0 確認理解
數字沒檢查換主題→K 第 8 項
計數錯階段 3→C0 程式檢查
推論混進筆記生成時→寫 raw 時
錯誤越上游，下游越抓不到

來源：reports/reflection.md

所以我把檢查往前移。最重要的是 R0：需求和主題沒確認清楚，流程不准開始。另外，檢查項目要跟著主題調整，財報主題就要檢查數字。學到的一句話是：錯誤越上游，下游越抓不到。
結尾

收穫與繳交位置

  • 錯誤越上游，下游越抓不到
  • 先確認需求和主題，再開工
  • 檢查要寫成程式，也要跟著主題調整
  • 所有檔案都在 GitHub repo
